Darwin → Melbourne 移动开发技能补齐路线图

适用人群：33 岁，约 10 年 Android，约 4 年 Flutter；计划 2027 年 6 月前往 Darwin，优先获取 Darwin 本地经验，接受全澳洲远程，数年后倾向 Melbourne。

主目标：Darwin 本地备选：全澳洲 Remote长期：Melbourne Senior/Lead原则：短期可交付

一、先给结论

不要同时学习十几个方向。你的核心优势已经是成熟的 Android/Flutter 交付能力；短期最划算的补缺不是重学前端、后端、DevOps、数据和云，而是构建一条能被 Darwin 和 Melbourne 雇主识别的“移动端 → 应用/API → 可靠交付”证据链。
  1. 第一优先：现代 Android（Kotlin、Jetpack Compose、Coroutines/Flow、架构、测试）——这是你去 Melbourne 最直接的增值，也是 Darwin 纯移动岗出现时的最强竞争力。
  2. 第二优先：Flutter 生产化和原生互操作——让你能投 Cross-platform、Flutter、Mobile Software Engineer，而不是只证明“会写 Flutter 页面”。
  3. 第三优先：API/Integration 基础（REST、认证、JSON/XML、重试、SQL、一个后端栈）——这是 Darwin 目前最明显的岗位缺口，也是本地 Application/Integration Developer 的桥梁。
  4. 第四优先：测试、CI/CD、Docker、云部署和可观测性——让简历符合澳洲 JD 的“能交付和支持生产系统”，而不只是客户端开发。
  5. 同步进行：英文、系统设计和行为面试。建议技术补缺投入约 50%，英文 30%，面试 20%；最后 8 周调整为 30% / 35% / 35%。

四、短期学习边界：学什么，不学什么

必须掌握到“能面试/能交付”

  • Kotlin：Coroutines、Flow、sealed/error model、泛型、测试。
  • Compose：state、recomposition、navigation、responsive UI、accessibility。
  • Android：模块化、Clean/MVVM、Room、Retrofit/OkHttp、WorkManager、性能。
  • REST/API：OAuth/JWT 概念、HTTP、分页、缓存、重试和 OpenAPI。
  • JUnit/Mock/Compose UI test、GitHub Actions、Docker Compose、PostgreSQL。

理解并能展示，不追求专家

  • Azure/AWS 基本服务、部署和 secrets。
  • Kafka/RabbitMQ 的消息、重试、死信队列概念。
  • XML、企业集成、API gateway 和系统边界。
  • iOS/Swift 或 React Native/TypeScript 基础。
  • 安全：OWASP Mobile、密钥管理、PII、最小权限。

短期明确不投入

  • 同时深入 C#/.NET、Java/Spring、Node、React、Swift、RN。
  • Salesforce/Vlocity、ArcGIS、Windows Server、网络硬件。
  • 为了证书而考多个云证书；先做可运行项目。
  • 从零学习数据科学、AI 算法等与目标岗位不直接相关的方向。

八、岗位投递策略

Darwin 本地优先

  • 主搜：Senior Software Engineer、Application Developer、Mobile Application Developer、Integration Developer。
  • 优先雇主生态：NT Government、Charles Darwin University、医疗、社区服务、当地 IT 服务商、允许非公民申请的承包商。
  • 遇到 Australian Citizen、Baseline clearance、NV1，先检查资格，不要把它当普通技术缺口。
  • 明确表达愿意 onsite、参与小团队、做跨职能交付和 fixed-term contract。

全澳洲 Remote 备选

  • 确认“可从 NT 工作”，不只看页面上的 Remote 标签。
  • 优先 native Android、Flutter、Mobile Software Engineer；其次 API/Application。
  • 询问时区、税务/payroll、设备、出差、办公室频率和是否需要澳洲地址。
  • 远程工作能积累澳洲项目经验，但对 Darwin 本地 network 和在地雇主信号弱于 Darwin onsite。

为 Melbourne 提前布局

  • 保持 Kotlin/Compose 主线，不要为了 Darwin 完全转离移动端。
  • 每 6 个月更新一次英文 portfolio、架构案例和量化成果。
  • 补充支付、安全、可靠性、A/B、产品协作等大团队关键词。
  • 逐步积累 mentoring、技术决策和跨团队影响力，目标 Senior/Lead，而非重新从 mid-level 开始。

九、不要把本地经验和移民等同

Darwin 本地工作经验对简历、推荐人、澳洲工作方式和雇主网络有帮助，但不会自动等于绿卡资格。签证、职业清单、ACS 评估、英语、年龄、州/领地提名、雇主担保、工资和当期政策需要分别核对；不要为了“本地经验”接受明显不匹配且无法形成 ICT 专业履历的岗位。
  • 第一份工作优先选择能留下真实 software/application/integration 职责、正式合同、可核验推荐人和清晰职位名称的工作。
  • 保留合同、职位描述、pay slips、super、职责证明和项目成果；以后职业评估或签证材料可能需要。
  • 目标是在 Darwin 做 1–3 年“可迁移”的澳洲 ICT 工作，再根据岗位密度、签证和个人偏好转 Melbourne。

十、完成标准（不是“学过”标准）

  • □ 能在 15 分钟内启动自己的 Android、Flutter、API、DB demo。
  • □ 能画出系统架构并解释客户端、API、数据库、第三方集成的边界。
  • □ 能解释 timeout、retry、idempotency、cache、offline、auth 和 PII。
  • □ CI 能自动运行 lint、unit test、integration test，并生成构建产物。

  • □ 具备三套针对岗位的简历：Mobile、Software Engineer、Application/Integration。
  • □ 投递前已确认签证/工作权、Darwin onsite 或 Australia-wide remote 条件。
